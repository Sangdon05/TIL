## UploadFile

- 파일 크기가 작을 떄는 메모리를 사용하지만, 일정 크기를 넘으면 임시 폴더에 나누어 쓰기 시작
- 서버 메모리 사용량을 일정 수준 이하로 유지하므로 메모리 부족으로 인한 서버 멈춤을 막을수 있다.

## 백그라운드 작업

- 오래 걸리는 작업이 시작되면, 웹 브라우저는 응답이 올 떄까지 멈춰있어야 한다.
- 서버에서 대기 목록(큐)에 등록하여 관리

## 파일 스트리밍 처리 (StreamingResponse)

- 서버에 저장된 대용량 파일을 데이터 청크 단위로 나누어 전달하는 비동기 제너레이터와 함께 작동
- 청크(Chunk)란?
	- 일정한 크기로 분할한 데이터 조각
- `yield`로 청크 단위로 나누어서 반환

## ORM (Object Relational Mapping)

- DB는 table로 데이터를 사용하고, python은 Object로 데이터를 사용한다.
	- 중간에서 통역을 도와주는 도구
- 복잡한 데이터베이스 명령문을 사용하지 않고 순수 파이썬으로 제어 가능
- 사용 패키지
	- `sqlalchemy`
		- ORM
	- `asyncpg`
		- postgresql 비동기 드라이버
	- `greenlet`
		- 경량 쓰레드 도구

## 커넥션 풀 (Connection Pool)

- 데이터베이스와의 연결 통로를 미리 여러개 열어두고 돌려쓰는 대기실 시스템
- `sqlalchemy` 커넥션 풀 설정 주요 옵션
	- `pool_size`: 기본 여결 통로 개수
	- `max_overflow`: 최대 예비 연결 개수
	- `pool_timeout`: 최대 기기 시간
	- `pool_pre_ping`: 연결 사전 확인 여부
		- 데이터베이스와 연결이 살아있는지 테스트
		- `select 1`과 같은 간단한 쿼리를 날린다.
	- `pool_recyle`: 자동 교체 주기

## 동시정 문제와 비관적 락 (Pessimistic Lock)

- 경합 상태 (Race Condition)
	- 예로 동시에 남은 상품의 재고를 확인하고 결제되어 중복 결제가 되는 현상
	- 데이터를 읽을 떄부터 다른 사람이 수정하지 못하도록 행에 자물쇠를 채우는 방식을 **비관적 락**이라고 한다.
- `@asynccontextmanager`
	- 서버나 특정 기능이 시작될 때 미리 준비해야 할 작업
	- 끝날 때 안전하게 정리해야할 작업
	- 두작업을 묶어서 관리해주는 비동기 도구
