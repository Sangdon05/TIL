## Sequence To Sequence Architecture

- 순환 신경망 이용
- 주로 번역에서 사용 목적으로 연구
- 인코더 - 디코더
	- 인코더: 문장을 이해하는 역할 (컨텍스트 벡터 생성)
		- $(h_{t},c_{t}) = \text{LSTM}(x_{t}, (h_{t-1},c_{t-1}))$
			- $h_{t}$: 은닉 상태 (단기 기억)
			- $c_{t}$: 셀 상태 (장기 기억)
			- $x_{t}$: 현재 시점에 입력된 단어 벡터
			- $(h_{t-1},c_{t-1})$: 직전 시점까지 누적된 인코더의 기억 상태
		- 컨텍스트 벡터
			- 컨텍스트 벡터(Context Vector): $C = (h_{T},c_{T})$ (마지막 시점 $T$의 기억 상태를 압축)
	- 디코더: 문장 생성하는 역할 (인코더의 컨텍스트 벡터를 초기 상태로 전달받음)
		- $(s_{t},d_{t}) = \text{LSTM}(y_{t-1}, (s_{t-1},d_{t-1}))$
		- 교사 강요(Teacher Forcing) 기법
		- 문장 시작 토큰: `<sos>` or `<s>` (Start Of Sequence)
		- 문장 종료 토큰: `<eos>` or `<e>` (End Of Sequence)

## Attention Mechanism (기법)

- **핵심 아이디어**: 인코더의 마지막 상태 하나만 압축(정보 병목)하지 않고, **모든 시점의 은닉 상태(Hidden States)를 보관하여 디코더가 필요한 시점마다 선택적으로 주의 집중(Attention)**
- **Q, K, V (Query, Key, Value)**:
	- **Query ($Q$)**: 무엇을 찾고 있는가? (현재 디코더 시점의 은닉 상태 $s_t$)
	- **Key ($K$)**: 어떻게 찾을 것인가? / 이름표 (인코더의 각 시점 은닉 상태 $h_i$)
	- **Value ($V$)**: Key에 매핑된 실제 의미 정보 (인코더의 각 시점 은닉 상태 $h_i$)
- 어텐션 연산 3단계 흐름
	- 유사도 측정 
		- $\text{Score}(Q, K) = Q \cdot K^T$
		- 디코더의 현재 상태($Q$)와 인코더의 각 단어 이름표($K$)를 내적하여 단어 간의 유사도 점수를 계산합니다.
	- 가중치 분배 
		- $\text{Attention Weights} = \text{Softmax}(\text{Score})$
		- 유사도 점수에 소프트맥스 함수를 적용하여, 총합이 1(100%)이 되는 확률 분포 형태의 가중치로 변환합니다.
	- 가중합 계산
		- $\text{Context Vector} = \sum (\text{Attention Weights} \times V)$
		- 계산된 가중치를 각 Value($V$) 벡터에 곱한 후 모두 더하여, 현재 시점에 필요한 최종 요약 벡터(Context Vector)를 생성합니다.

## Transformer Architecture

인코더 블럭
- 잔차연결 (값이 갑자기 높아진다) -> 층 정규화 (과적합이 일어나지 않도록 처리)
- 피드포워드 네트워크
- 입력 차원과 출력 차원이 동일
- 인코더 블럭 x n (6, 9, 12, ...)

디코더 블럭
- Masked Multi-Head Attention
- Cross Attention
- 피드 포워드 네트워크
- 디코더 블럭 x n (6, 9, 12, ...)

## 데일리 테스트 오답 노트

Seq2Seq 모델에서 인코더가 디코더에 전달하는 '컨텍스트 벡터'의 내부 구성 요소로 옳은 것은?

>LSTM은 단기 기억(은닉 상태)과 장기 기억(셀 상태)을 함께 유지하므로, 인코더가 압축한 컨텍스트 벡터도 이 두 상태를 튜플로 묶어 디코더에 전달합니다. 나머지 선지는 컨텍스트 벡터의 실제 구성과 무관한 개념입니다.
