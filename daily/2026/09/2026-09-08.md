## 서브쿼리

SELECT문 안의 SELECT

스칼라 서브쿼리: 단일값
- `SELECT <서브쿼리> FROM ...`

인라인 뷰: 가상 테이블 -> 실제 물리적 테이블 아니고, 조회 결과를 가지고 테이블처럼 사용가능한 임시 테이블
- `SELECT ... FROM <서브쿼리>`

상관 서브쿼리: 내부쿼리의 결과를 외부쿼리가 사용
- `SELECT ... FROM ... WHERE <서브쿼리>`

## ACID 원칙

- A - Atomicity 원자성
	- 모두 성공 또는 모두 실패
- C - Consistency 일관성
- I - Isolation 격리성 
- D - Durability 지속성

## 진단 퀴즈 오답 노트

>SQL 구문의 작성 순서는 SELECT부터 시작하지만, 실제 실행 순서는 대상 테이블을 찾는 FROM에서 시작합니다. 이후 개별 행 필터링(WHERE), 데이터 그룹화(GROUP BY), 집계 결과 필터링(HAVING), 조회할 열 선택 및 별칭 부여(SELECT), 마지막으로 정렬(ORDER BY) 순서로 쿼리가 실행됩니다.

>WHERE절 서브쿼리는 외부 쿼리(Outer Query)가 실행되기 전에 먼저 연산됩니다. 이렇게 안쪽에서 동적으로 계산된 결과(예: 평균값 등)가 외부 쿼리의 조건으로 전달되어 필터링이 수행됩니다.

>FROM절에 사용되는 서브쿼리(인라인 뷰)는 외부 쿼리에서 하나의 임시 테이블처럼 취급되므로, 반드시 참조할 수 있는 별칭(AS 별칭명)을 지정해야 합니다. 주어진 코드에는 괄호 뒤에 별칭이 빠져 있어 오류가 발생합니다.
