## 토크나이져 (Tokenizer)

BPE
- 데이터에서 가장 빈번하게 등장하는 글자 쌍으로 반복적으로 병합하여 어휘 사전을 구축하는 알고리즘
- 현대 주요 대형 언어 모델의 기반
WordPiece
- BPE와 유사하게 빈도 기반으로 동작
- 통합했을 때 전체 코퍼스의 우도를 얼마나 높은지를 통계적으로 계산하여 분합
- BERT, KoBERT
SentencePiece
- 사전 공백이 존재하지 않아도 처리 가능한 독립형 전처리
- 공백 자체를 특수 기호(예: `_`)로 취급하여 처리
- 띄어쓰기 규칙이 불규칙한 한국어나 공백이 없는 중국어, 일본어 처리에 효과적

## SQL

DDL (Data Definition Language): 데이터 정의어
- CREATE: 
	- Table 생성
		- ```sql
			CREATE TABLE <테이블명> (
				<컬럼명> <데이터 타입> <[제약조건, ...]> <[DEFAULT 값]> <[REFERENCES 테이블명(컬럼명)]>,
				<컬럼명> <데이터 타입> <[제약조건, ...]>,
				.
				.
				.
				PRIMARY KEY(<컬럼명>, ...)
			)
		  ```
			- 제약조건: `[]`는 옵셔널 입력을 의미
				- PRIMARY KEY
					- 중복허용하지 않는다.
					- 비어있는 값을 허용하지 않는다. (Not Null)
				- NOT NULL
					- 비어있는 값을 허용하지 않는다.
					- 필수 항목(컬럼)
				- UNIQUE
					- 중복허용하지 않는다.
					- NULL은 중복 가능
					- NULL을 허용하지 않을 경우 NOT NULL과 함께 사용한다.
				- CHECK
					- 특정 조검에 해당하는지 확인: 비교, 논리 연산자 등등 사용가능
						- AND, OR, NOT
				- DEFAULT
					- 직접 값 지정, 내장 함수 호출, 내장 상수
					- CURRENT_TIMESTAMP: 현재 날짜와 시간
				- 복합키: 여러 컬럼의 조함으로 기본키를 만드는 경우
					- `PRIMARY KEY(<컬럼명>, ...)`
				- 외래키 (Foreign key)
					- `REFERENCES 테이블명(컬럼명)`
					- 참조 무결성 제약조건 적용
					- 부모쪽 테이블에 없는 참조값은 자식테이블이 사용할수 없다.
					- 부모쪽 레코드를 참조하는 자식 레코드가 있으면 부모쪽 레코드를 삭제할수 없다.
					- ON DELETE
						- CASCADE: 부모 레코드가 삭제되면 자식 레코드도 같이 삭제
						- SET NULL: 부모 레코드가 삭제되면 자식 레코드의 참조 컬럼의 값을 NULL로 교체
- ALTER
- DROP
	- ```sql
	  DROP <대상>
	  ```
	  대상은 테이블, 인덱스 등이 올수 있다.
	- 테이블 삭제
		- ```sql
		  DROP TABLE <테이블명>;
		  ```
- TURNCATE <- 위험한 명령어... 조심조심
	- 테이블의 구조 유지, 초기화
	- `TURNCATE TABLE 테이블명`

DML (Data Manipulation Language): 데이터 조작어
- INSERT
	- ```sql
	  INSERT INTO <테이블명> ( 컬럼명, ... ) VALUES (값, ...);
	  ```
- UPDATE
- DELTE

DQL (Data Query Language): 데이틔 질의어 (DML에 포함되지만 분리해서 불릴때도 있음)
- SELECT

DCL (Data Control Language): 데이터 제어
- GRANT: 권한 부여
- REVOKE: 권한 취소

TCL (Transaction Control Language)
- COMMIT: 데이터를 DB에 영구반영
- ROLLBACK: COMMIT 전 반영 내용으로 되돌리기
	- COMMIT 이후는 사용불가

데이터 타입 - 자동증감 기능
- 표준어: INT GENERATED ALWAYS AS IDENTITY
- postgreSQL
	- SERIAL (4byte 정수)
	- BIGSERIAL (8byte 정수)

데이터 무결성 제약 조건
- 도메인 무결성 제약조건: 자료형
- 개체 무결성 제약조건: 기본키
- 참조 무결성 제약조건: 외래키

데이터베이스 정규화: 데이터 중복과 이상현상을 개선하기 위해서 테이블의 구조를 단계적으로 개선하는 과정
- 제 1 정규형 (1NF): 원자값 유지
	- 하나의 레코드에는 하나의 값만 저장하기
- 제 2 정규형 (2NF): 
	- 복합키의 일부에만 의존하는 열 분리하기
- 제 3 정규형 (3NF): 
	- PK가 아닌 컬럼끼리의 의존 관계 제거하기

## 데일리 퀘스트 오답 노트

수강 신청 테이블에서 student_name이 student_id에만 의존하고 course_name이 course_id에만 의존하는 경우, 이를 개선하기 위해 적용하는 정규화 단계는 무엇인가요?

>2NF는 복합키를 사용하는 테이블에서 복합키 전체가 아니라 일부 키에만 의존하는 열을 분리하는 단계입니다. 1NF는 한 칸에 하나의 값만 저장하는 단계이고, 3NF는 PK가 아닌 컬럼 간의 의존 관계를 제거하는 단계이므로 이 사례와는 맞지 않습니다.
