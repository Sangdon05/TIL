## 4 계층 아키텍쳐

1. 표현 계층 (Presentation Layer)
2. 응용 서비스 계층 (Application Layer)
3. 도메인 계층 (Domain Layer)
4. 인프라 계층 (Infrastructure Layer)

### 도메인 계층

- 특정 영역에 대한 전문 지식
- 비지니스 영역의 해결해야 할 문제를 해결하기 위한 지식
- 도메인 전문가와 소통 -> 도메인 지식을 상승 시켜야한다.
	- 도메인 용어로 소통해야한다.
	- 용어 사전
	- 유비쿼터스 언어
- 도메인 모델
	- 비지니스 요구사항(도메인 규칙)들을 코드로 구체화 해나가는 과정
	- 도메인 계층에서 진행
- 도메인 서비스
	- 추상 클레스
	- 외부 기능을 접근하기 위해서 추상 클레스 생성
	- 인프라 계층에서 구현
	- Container에서 연결 -> 응용 서비스 계층에서 구현체 주입
- 관련성이 있는 객체들의 집합 (애그리거트 - Aggregate)
	- 같은 책임과 일관성 보장
	- Entity (Root)
	- VO (Value Object)
	- Entity를 통해서만 관련 VO를 접근해야한다.
- 책임 경계성 (Bounded Context)
	- 각 책임에 따라 같은 개념이라도 요구사항이 다를수있다.
	- 회원, 작성자, 주문자 등등 같은 가입 회원이지만 책임마다 다른 속성을 요구하고 다르게 표현해야 관계성을 낮출수있다.
- 도메인 이벤트
	- 단일책임의 원칙에 의해 책임 경계 밖의 일을 해야할때 다른 도메인으로 작업 요청을 한다.
- 레포지토리 (Repository)
	- 추상 클레스
	- 인프라 계층에서 구현
	- Container에서 연결 -> 응용 서비스 계층에서 구현체 주입
### 인프라 계층

- 특정 구현 기술
- 도메인, 응용 계층에서 필요한 실 구현체를 관리한다.
