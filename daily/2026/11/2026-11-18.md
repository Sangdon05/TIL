
## Re-ranking
>가볍고 빠른 1차 검색기로 후보 문서들을 빠르게 가져온 뒤, 문맥과 뉘앙스를 깊이 이해하는 고성능 리랭커(Cross-Encoder 등)로 순위를 정리하게 다시 매기는 2단계(Two-Stage) 최적화 기술

- 2단계(Tow-Stage) 검색 필요성
	- 1단계 (Retrieval, 후보 추출): 관련 가능성이 높은 문서 10 ~20건을 빠르게 선별
	- 2단계 (Re-ranking, 정밀 재정렬):  1 단계 문서들을 대상으로 질문과의 실제 의미 관계를 심층 분석하여 1~3위를 다시 결정
	- 처리 효율성: 입력 대상을 극적으로 줄이면서도 최종 정확도는 최고 수준으로 유지 할수있다.
- Bi-Encoder (기존 벡터 검색)
	- 질문과 문서를 각각 독립된 좌표로 변환한 뒤 각도 차이만 계산하므로 매우 빠르지만, 단어 간의 세부 문맥 상호작용을 놓치기 쉽다.
	- 전반적인 주제 유사도 파악
	- 전체 데이터에서 상위 후보군 선별
- Cross-Encoder (리랭커)
	- 질문과 문서를 하나의 입력창에 나란히 붙여서 모델에 넣고, 두 문장이 얼마나 긴밀하게 맞물리는지 직접 교차 연산하므로 정확도가 뛰어나다.
	- 문장 간의 세밀한 인과관계 및 일치도 파악
	- 선별된 후보군 내 최종 순위 뒤집기 및 재배치

## 컨텍스트 압축(Context Compression)
>검색된 문서 전체를 그대로 전달하지 않고, 질문과 연관된 핵심 내용만 발췌하거나 불필요한 문장을 제거하여 전달하는 검색 최적화 기술

- Lost in the Middle (중간 정보 누락): 긴 문맥의 중간에 위치한 세부 사실을 망각하는 경향
- 맥락 압축 2단계 동작 원리
	- 1단계 (기본 탐색): 키워드 검색기(BM25) 또는 벡터 검색기가 질문과 관련된 후보 문서를 빠르게 가져온다.
	- 2단계 (문맥 압축): 문서 압축기(Compressor)가 질문을 기준으로 문서를 일고, 무관한 문장을 삭제하거나 핵심 문장만 추출
- 노이즈 제거 (Denoising): 질문과 무관한 주변 문장을 프롬프트에서 배제하여 환각을 억제하고 답변의 정확도를 극대화하는 작업

## 질의(Query) 유형

- 대표적인 3가지 질의 유형
	- 고유명사•단순 키워드형 (Exact Keyword): 특정 코드, 약어, 고유 명칭을 포함하는 질문
	- 의미 탐색형 (Semantic/Intent): 일상적인 구어체나 동의어로 의미를 묻는 질문
	- 복합 조건형 (Complex Multi-condition): 다중 제약 조건이나 상황 설명이 혼합되어 문맥 해석이 필요한 질문
- 적합도
	- 키워드 검색 (BM25)
		- 특정 단어의 빈도와 희소성 계산
		- 고유명사, 약어, 규정 조합 번호 검색
		- 단어 불일치 시 검색 누락(Vocabulary Mismatch)
	- 벡터 검색 (Vector/Semantic)
		- 다차원 숫자 배열로 변환 후 의미 거리 계산
		- 동의어, 유의어, 구어체 기반 문맥 검색
		- 전문 용어 왜곡, 지나치게 포괄적인 유사도 매칭
- 검색 실패 분석 (Retrieval Failure Analysis): 검색기가 잘못된 문서를 도출한 기술적 원인을 규명하여 향후 하이브리드 검색이나 가중치 튜닝의 근거로 삼는 작업

## 검색 전략 선택•개선

- 질의 유형별 최적 검색 전략 매핑
	- 고유명사•단순 키워드
		- 키워드 검색 (BM25)
		- 시스템 코드, 약어, 규정 조항 번호 포함
		- 단어 형태의 100%일치가 핵심, 왜곡 없는 텍스트 매칭이 유리
	- 의미 탐색형
		- 벡터 검색 (Vector)
		- 일상 구어체, 동의어, 상황 묘사 중심
		- 문맥적 의도를 파악하는 다차워 임베딩 유사도가 유리
	- 복합 조건형
		- 벡터 검색 또는 Hybrid
		- 여로 저건과 맥락이 얽힌 복합 질문
		- 전체 문맥을 포괄적으로 해석해야 하므로 의미 기반 탐색이 우선됨
- 동적 라우팅 (Query Routing) 원리
	- 분류기(Router)가 먼저 질문의 의도 분석
	- 고유 명사는 키워드 검색기, 서술형 문장은 벡터 검색기로 분기 시켜 검색 누략 방지
- 파이프라인 개선 (Pipeline Refinement): 단일 검색 방식의 한계로 발생하는 검색 실패를 다중 검색기 동적 연결을 통해 보완하는 작업

## Query 번환 기법
>HyDE, Query Rewrite, Query Routing, Memory 기반 검색

- Query 변환 (Query Transformation)
	- 사용자의 자연어 질문을 검색 시스템이 이해하기 쉬운 최적의 표현으로 재작성하는 전처리 기법
- 검색 전단계(Pre-Retrieval) 최적화의 필요성
	- 어휘 불일치 해소
	- 모호성 제거
	- 검색 품질 사전 확보
- 질의 특성별 4대 변환 기법
	- 질문 재작성 (Query Rewrite)
		- 맞춤법 교정 및 핵심 명사 중심 재구성
		- 은어•오타가 포함된 경우
		- 질문이 지나치게 짧은 경우
	- 가설 문서 임베딩 (HyDE)
		- 가상의 예상 답변 문서를 먼저 생성 후 검색
		- 질문과 정답 문서 간의 문제•전문성 격차가 큰 경우
	- 질문 라우팅 (Query Routing)
		- 질문의 성격을 판별하여 저장소 경로 지정
		- 복수의 특화 데이터베이스가 존재하는 경우
	- 대화 맥락 반영 (Memory 기반 검색)
		- 직전 대화 기록을 참조해 생략된 대명사 복원
		- 멀티턴 챗봇 환경에서 연속된 질문을 처리하는 경우
- 문맥 복원 (Contextualization): 대화 이력을 바탕으로 현재 질문의 생략된 주어 및 대명사를 구체적인 명사로 채워 넣는 작업


## RAG 평가 지표

- 검색 품질 지표
	- Context Precision(문맥 정밀도)
		- $\frac{TP}{TP + FP}$
			- 예) 근거 문서 5개, 정답기여 문서 3 -> $\frac{3}{5}$
	- Context Recall(문맥 재현률)
		- $\frac{TP}{TP + TN}$
			- 맞춘 문서 수 / 총 정답 분서 수
		- 재현률이 낮으면 문서 수를 늘리거나 청킹 크기를 낮춰본다.
- 성능 지표 F1-Score (조화 평균)
	- F1-Score = 2 * (Precision * Recall) / (Precision + Recall)
- 문서가 1개일 경우
	- 질문 답변에 기여한 문장 / 청크에 포함된 전체 문장


## 생성 품질 지표

- 신뢰도 (Faithfulness)
	- 응답을 입증 가능한 문장 수
	- 신뢰도 = 문서에서 입증 가능한 진술 수 / 답변에서 추출한 전체 진술 수
	- 환각 현상 판단 지표로 사용할수있다.
	- 개선 방향
		- 프롬프트 개선
			- 참고 문서만을 근거해서 찾을수있도록 가이드
			- 없으면 모른다고 답변하도록 가이드)
		- LLM 품질 이슈
			- LLM 모델 교체
- 답변 관련성 (Answer Relevancy)
	- 질문과 답변의 의미적 연관성 판단
	- 임베딩 거리로 판단 -> BI Encoder
	- 트랜스포머 인코더 기반으로 판단 -> Cross Encoder
	- 개선 방향
		- 노이즈 제거
		- LLM 모델 교체

## Memory 기법

- RAG 기법 이용
	- 모든 대화 목록을 넣게되면 Context Window 문제가 발생
	- 현재 맥락에 낮는 대화를 검색 -> 요약하여 대화 목록 입력
