## 임베딩

- 배치 처리(Batch Processing)
	- 여러 문장을 한 묶음으로 묶어 단 한 번의 네트워크 요청으로 처리하는 방식
- `embed_documents`
	- 여러 텍스트 조각들을 리스트 형태로 전달하여 다수의 벡터를 동시에 생성
- 비용 관리 및 캐싱(Caching)
	- 한번 계산된 인베딩 결과를 로컬 파일로 저장하여 중복 비용 발생을 원천 차단 

## 벡터 DB

- PostgreSQL + pgvector 원리
	- pgvector 확장
	- postgresql에서 이반 테이블 데이터와 임베딩 벡터 데이터를 하나의 데이터베이스 안에서 통합 관리
	- 컬렉션(Collection)과 테이블 분리 구조
		- 컬렉션 메타데이터
			- langchain은 db 내부에서 컬렉션 정보를 `langchain_pg_collection` 테이블로 관리
		- 임베딩 데이터 적재
			- 실제 본문 텍스트와 벡터 좌표값은 `langchain_pg_embedding` 테이블에 저장되어 관리
- `PGVector`를 이용한 벡터 DB 저장(Upsert)
	- 개발자가 임베딩을 일일이 수동 연산할 필요 없이 모듈 내부에서 바인딩된 임베딩 모델을 자동으로 호출하여 데이터베이스에 배치(Batch) 단위로 일괄 적재
	- `add_testx`
	- 고유 식별자(ID) 부여
		- 각 청크에 식별자를 부여하여 데이터 중복 적재를 방지하고 업데이트 처리
- 질의응답
	- 벡터 유사도 검색 실행
		- `similarity_search`: 사용자 질의를 실시간으로 임베딩한 후, DB 내 벡터 컬럼과의 거리를 계산해 최적의 문서 추출

## 메타데이터 스키마

- 설계 원리
	- 검색 단계에서 불필요한 탐색을 줄이기 위해 정의하는 데이터 규격
	- 메타데이터의 개념
		- 본문 텍스트 외에 문서의 출처, 작성일, 카테고리 등을 기록한 설명 데이터
	- 벡터 검색의 한계 보완
		- 개정 전 규정과 최신 규정처럼 시점이나 대상이 다른 문서를 정확히 분리
- 구성 요소
	- `source`: 원본 문서 파일명 또는 출처 URL, 특정 문서 출처 번위 한정
	- `category`: 문서의 업무 분류, 도메인별 검색 대상 필터링
	- `year`: 규정 적용 연도, 최신 개정 규정 우선 필터링
	- `author`: 작성 부서 또는 담당자, 담당 부서별 자료 분류
	- 이외 필요한 요소 추가하여 관리
- `use_jsonb=True` 설정하여 유연하고 빠른 인덱싱이 가능한 JSONB 형식 지정

## 인덱싱 파이프라인 통합/증분 갱신

- 인덱싱 파이프라인 통합
	- 문리되어있던 문서 로딩, 분할, 임베딩, DB 적재 과정을 단일 흐름으로 결합한 자동화 프로세스
	- 개별 실행의 한계
		- 단계별 코드를 수동으로 실행하면 작업 누락 및 데이터 불일치 발생
	- 파이프라인 결합
		- 입력 경로만 전달하면 데이터 전처리부터 벡터 DB 저장까지 자동으로 완료
- 증분 갱신
	- 기존 저장소의 문서 해시값을 비교하여 신규 추가되거나 변경된 문서만 선별하여 저장하는 기술
	- 전체 재색인 문제
		- 기존 문서를 매번 전체 재저장하면 API 비용, DB 입출력 병목 발생
	- `SQLRecordManager`
		- 문서의 출처(Source)와 내용의 해시(Hash) 값을 기록하는 일종의 작업장부
	- `index()`: 조회하여 새로 생성된 청크는 추가(add), 수정된 청크는 업데이트(Update), 변경이 없는 청크는 건너뛰기(skip)
		- `cleanup`
			- `none`: 증분 관리 안함
			- `incremental`: 중복된 레코드가 있으면 삭제하고 새로 추가
			- `full`: 전체를 삭제하고 다시 추가

## 검색 전략

- TF-IDF (Term Frequency-Inversion Document Frequency)
	- 빈도수에 따라서 가중치를 부여하는 기법
	- 한문서에서 자주 등장 (중요 단어) -> 가중치 높게
	- 전체문서에서 자주 등장 (중요 단어가 아님) -> 가중치 낮게
- BM25
	- TF-IDF를 활용한 방식
	- 임계치 설정 (25)
- RRF (Reciprocal Rank Fusion)
	- 상호 순위 융합
	- 등수만으로 계산
- Query 변환
	- 사용자의 질문 -> LLM -> 검색에 유리한 질문으로 변환
	- Hyde: 가장 문서 기법
		- 질문 -> LLM -> 관련있는 가상 문서 생성 -> vector db 검색
