## Alchemy ORM

### 공통 설정
- DeclarativeBase
	- 상속받은 모델들의 테이블을 자동 관리할 수 있다.
- create_async_engine
- async_sessionmaker
	- rollback을 위하여 `autoflush`, `expire_on_commit`은 `False`로 설정한다.

### 테이블 모델 및 스키마

- Pydantic 모델을 생성할 수 있도록 허용하는 설정
	- `ConfigDict(from_attributes=True)`

| **분류**           | **db.scalars(stmt) 호출 시 (ORM 엔티티 추출)** | **db.execute(stmt) 호출 시 (Row 튜플 추출)**  | **결과가 0건일 때**    | **결과가 2건 이상일 때**        | **권장 사용 시나리오**                               |
| ---------------- | -------------------------------------- | -------------------------------------- | ---------------- | ----------------------- | -------------------------------------------- |
| **정확히 1건**       | .one()                                 | .one() / .scalar_one()                 | NoResultFound 예외 | MultipleResultsFound 예외 | 반드시 존재해야 하는 데이터 조회 (데이터 무결성 엄격 검증)           |
| **0건 또는 1건**     | .one_or_none()                         | .one_or_none() / .scalar_one_or_none() | None 반환          | MultipleResultsFound 예외 | **UNIQUE 제약이 걸린 컬럼 조회** (예: 이메일 중복 확인, 로그인)  |
| **첫 번째 1건**      | .first() _(또는 await db.scalar(stmt))_  | .first() / .scalar()                   | None 반환          | 첫 번째 행만 반환 (예외 없음)      | 정렬 후 최신 1건 조회, 존재 여부 단순 확인                   |
| **모든 다건 (List)** | .all()                                 | .all()                                 | 빈 리스트 [] 반환      | 모든 행 반환                 | 목록 조회, 검색 결과 반환                              |
| **단건 PK 조회**     | await db.get(User, pk)                 | -                                      | None 반환          | PK이므로 불가능               | **기본 키 단건 조회 표준** (Identity Map 1차 캐시 우선 활용) |

- execute() vs scalars() 반환 형태의 차이
	- db.execute(stmt) 사용 시: Row(User, ) 튜플 형태로 감싸져 반환
	- db.scalars(stmt) 사용 시: ScalarResult로 껍질을 벗겨 ORM 엔티티 직접 반환
- 상황별 코드 패턴
	- UNIQUE 조건 단건 조회 (one_or_none)
	- 반드시 존재해야 하는 데이터 검증 조회 (one)
	- 정렬 후 최신 1건 가져오기 (first)
	- 다건 목록 조회 (all)

## 관계 매핑

- 단방향
	- 자식 테이블에 외래 키를 정의하고, 자식에서 부모로 향하는 단방향 관계 설정
	- `relationship`
- 양방향
	- 부모에서도 자식을 향하는 관계 설정
	- 로딩 전략 옵션
		- lazy="selectin"
			- 부모 조회 후 PK 목록으로 In 형태의 2번째 쿼리 실행
			- 비동기 지원
			- 1:N, N:M 컬렉션 조회의 필수 표준
		-  lazy="joined"
			- LEFT JOIN을 사용하여 단일 쿼리로 병합
			- 비동기 지원
			- N:1, 1:1 단건 객체 조회의 기본값
- 다대다 (N:M)
	- 두 엔티티 사이에 외래 키 2개로 구성된 연결 테이블(Association Table)을 Table 객체로 선언
	- relationship()에 secondary=연결테이블을 지정
	- 비동기 환경에서 태그 컬렉션을 안전하게 읽기 위해 lazy="selectin"을 적용

## 조건 연산자 및 동적 쿼리 패턴

- 조건 연산자
	- `or_`, `and_`, `not_` 함수
	- `|`, `&`, `~` 비트 연산자
	- 실무에서는 가독정을 위해 함수 형태 권장
- 문자열 검색 조건
	- `like("%kw%")`: 표준 와일드카드 직접 지정
	- `ilike("%kw%")`: PostgreSQL 전용 대소문자 무시 검색 <- 권장
	- `contains("kw")`: 앞위에 `%`를 자동으로 붙여줌
	- `icontains("kw")`: 앞위에 `%`를 자동 추가 + 대소문자 무시
	- `startwith("kw")`: 특정 접두사로 시작
	- `istartwith("kw")`: 대소문자 무시 접두사 일치
	- `endswith("kw")`: 특정 접미사로 끝남
	- `iendswith("kw")`: 대소문자 무시 접미사 일치
- 비교 및 범위 연산
	- `Col == val`, `Col != val`: 일치, 불일치
	- `Col > val`, `Col <= val`: 대소 비교
	- `Col.in_([1, 2, 3])`: 목록에 포함 여부
	- `Col.not_in([1, 2, 3])`: 미포함 여부
	- `Col.between(low, high)`: 범위 검색
- NULL 처리
	- `Col.is_(None)`: NULL 값 확인
	- `Col.is_not(None)`: NOT NULL 확인
- 관계 컬렉션 대상 조건
	- `.any()`: 1:N 또는 N:M 관계에서 특정 조건을 만족하는 자식이 하나라도 있는지 검사
		- `EXISTS (SELECT 1...)`
	- `.has()`: N:1 또는 1:1 관계에서 부모 조건 검사
- 동적 다중 조건 필터링
	- `*conditions`로 언패킹하는 패턴이 가장 안전하고 깔끔
