## 임베딩과 벡터

- 임베딩
	- 임베딩은 단어나 문장이 지닌 의미를 다차원 공간의 좌표(숫자 배열)로 변환하는 기술
	- 의미 공간(Semantic Space)
		- 컴퓨터는 문자 자체를 계산할 수 없음, 모든 글자를 숫자로 변환
		- 의미가 유사한 문장은 다차원 공간에서 서로 가까운 좌표에 위치
		- 단어와 문장 간의 관계르 ㄹ거리와 각도로 측정
	- 차원(Dimension)
		- 문장의 의미를 세부적으로 측정하고 분류하는 기준 축의 총 개수
		- 고차원 의미 공간을 통해 문맥, 어조, 전문 용어 등 복합 의미 반영
- 벡터
	- 벡터 간의 거리를 계산해 질문과 가장 관련성이 높은 문서를 찾아낸 뒤 LLM에 문맥으로 전달하여 최종 답변 생성
	- 코사인 유사도(Cosign Similarity)
		- 두 벡터가 가리키는 방향이 일치할수록 1에 가까워지고, 방향이 다를수록 0 또는 음수에 가까워진다.
	- 벡터 차원 수와 연산 속도는 검색의 정확도뿐만 아니라 벡터 DB 용량과 운영 비용에 직접적인 영향을 미친다.
	- 임베딘 단계에서 텍스트의 의미가 왜곡되거나 손실되면 엉뚱한 문서가 검색되어, 파이프라인 전체의 답변 품질이 떨어지는 치명적인 병목 지점이 된다.
- 임베딩 모델 선택시 고려 사항
	- 도메인 적합성
		- 전문 용어가 다수 포함된 문서는 해당 분야 용어를 학습한 모델을 채택
	- 인프라 비용
		- 차원이 높을수록 벡터 데이터베이스의 메모리 사용량과 인덱싱 비용이 선형적으로 증가
	- 다국어 지원 능력
		- 영어 이외의 언어일 경우 다국어 특화 모델인지 사전에 검증해야한다.

## 벡터 유사도
>벡터 간의 거리와 각도를 수학적으로 츠정하여, 의미적 유사성을 판별하는 핵심 척도

- 측정 방식
	- 코사인 유사도 (Cosign Similarity)
		- `-1`과 `1` 사이의 값을 가진다.
		- 자연어 검색에서 가장 표준적으로 사용
	- 유클리디안 거리 (Euclidean Distance)
		- 두 벡터 끝점 사이의 최단 직선거리 측정
		- 0에 가까울수록 유사
	- 내적 (Dot Product)
		- 두 벡터의 방향과 크기르 ㄹ동시에 반영
		- 단위 벡터로 정규화된 상태에서는 코사인 유사도와 수학적으로 동리한 결과
- ANN (근사 최근접 이웃) 검색
	- Approximate Nearest Neighbor
		- 대규모 벡터 공간에서 전수 조사를 피하고, 오차 범위를 허용하면서 탐색 속도를 수천배 향상시키는 고속 색인 기술
	- 완전 탐색 (K-NN)
		- 전수조사(Brute-force)
		- 모든 저장 벡터와 질의 벡터 간 거리를 비교
	- ANN
		- 사전 군집화하여 질의가 위치한 특정 영역 내부의 후보군만 압축 탐색
		- 약간의 검색 정확도(Recall) 양보, 대신 검색 속도를 획기적으로 개선

## 청킹 전략

- 청킹(Chunking)의 원리와 필요성
	- 방대한 텍스트 문서를 정보의 손실 없이 처리할 수 있도록 일정한 크기의 조각으로 나누는 작업
- 배경
	- 언어 모델과 임베딩 모델은 한번에 입력받을 수 있는 최대 토큰 수가 정해져 있다.
	- 너무 긴 문서를 통째로 임베딩하면 여러 주제가 섞여 벡터의 의미 표현력이 약화된다.
	- 질문과 연관성이 높은 핵심 문단만 선별, 인공지능에게 절달하하여 응답 속도와 정확도가 올라간다.
- 분할 전략
	- 고정 크기 분할(CharacterTextSplitter)
		- 지정된 글자 수로 분할
		- 연산 속도는 매우 빠르다.
		- 단어, 문맥 단절로 검색 정확도를 떨어뜨리는 한계 존재
	- <mark>재귀적 문자 분할</mark>(RecursiveCharacterTextSplitter)
		- 문단, 문장, 공백 순으로 구분자를 단계 적용해 의미 단위를 온전히 보존
		- 범용 텍스트 처리에 가장 최적화된 표준 청킹 방식
- 의미론적 분할(Semantic Chunking)
	- 작동 원리
		- 문장 단위로 분할 후 인접 문장 간의 벡터 유사도를 연속적으로 산출
		- 유사도가 설정된 임계값(Threshold) 이하로 경계면(Breakpoint) 탐지하여 청크를 분리
	- 기술적 특성
		- 청크 내 의미론적 응집도(Semantic Coherence)를 극대화해 검색 재현율(Recall)과 정확도 향상
		- 인덱싱 파이프라인 단계에서 다수의 임베딩 모델 추론이 강제되므로 레이턴시(Laytency) 및 API 비용 부담 수반
- 청크 크기와 오버랩 설정의 트레이드오프
	- 청크 크기와 오버랩 설정값에 따라 검색 정확도와 모델의 문맥 이해도 사이에 상충 관계 발생
	- 청크 크기가 작을 떄
		- 검색은 정밀해지지만 문장의 앞뒤 인과관계가 누락될수 있다.
	- 청크 크기가 클 떄
		- 문맥은 충분히 유지되지만 질문과 무관한 문맥이 포함되어 노이즈 발생
	- 오버랙(Chunk Overlap)
		- 앞 청크의 끝부분을 뒤 청크의 시작 부분에 중복 포함하여 경계면문맥 단잘을 방지
- 청크 크기별 트레이드오프
	- 소형 청크(50 ~ 100자)
		- 장점: 단답형 사실 검색에 유리
		- 단점: 앞뒤 인과관계 유실
		- 적합한 문서 유형: FAQ, 사전, 단순 단어 규정집
	- 중형 청크(200 ~ 500자)
		- 장점: 문맥과 검색 정밀도의 균형
		- 단점: 특수한 구조 분석 시 조정 필요
		- 적합한 문서 유형: 일반 학사 규정, 업무 메뉴얼
	- 대형 청크(800자 이상)
		- 장점: 문맥 보존 및 서사 이해 우수
		- 단점: 무관한 내용 혼입, 토큰 소모 증가
		- 적합한한 문서 유형: 계약서 전문, 법률 조항, 학술 논문

## 메타데이터 설계
>데이터 조각에 부착하는 `규격화된 신분증`

- 메타데이터(Metadata)의 원리와 필요성
	- 시간적 유쇼성 구분
		- 구버전과 최신 개정안을 날짜 필드로 명확히 분리
	- 문서 출처 추적성
		- 원본 문서의 위치와 근거 페이지 입증
	- 검색 연산 비용 절감
		- 조건에 맞는 데이터만 선별하여 처리 속도 높인다.
- 스키마 설계 및 분할 연계
	- 식별, 시간, 구조 정보를 균형 있게 정의해야 체계적인 필터링과 원본 역추적 가능
	- 3대 분류 체계
		- 식별 정보(Identity)
			- `source`, `doc_id`, `author`
			- 문서의 출처를 명시하고 답변의 인용 근거 제시
		- 시간 정보(Temporal)
			- `created_at`, `updated_at`, `year`
			- 구버전 정보 배제 및 최신 유효 문서 우선 선별
		- 구조 정보(Structural)
			- `section`, `page`, `chuck_id`
			- 원본 문서 내 위치 파악 및 인접 문맥 역추적 가능
- 필터링(Filtering) 원리
	- 검색 대상의 범위를 좁히는 `사전 거름망`
	- 필터링 메커니즘
		- 사전 필터링(Pre-filtering)
			- 메타데이터 조건을 충족하는 청크만 먼저 걸러낸 뒤 유사도 계산 수행
		- 사후 필터링(Post-filtering)
			- 전체 데이터를 대상으로 유사도 검색 수행 후 조건에 맞지 않는 결과를 버림
- 출처 추적성(Traceability)
	- 모델이 생성한 답변의 원본 파일 및 페이지 근거를 투명하게 검증할 수 잇는 신뢰성 지표


## 문서 로딩(Document Loading)

- 포맷 이질성 해소
	- PDF, 웹페이지, 워드 문서는 저장 구조가 달라 모델이 직접 읽을 수 없다.
- 표준화된 규격 변환
	- 모든 입력 데이터를 `page_content`(본문), `metadata`(속성) 구조로 일원화
- 파이프라인 연속성 보장
	- 메타데이터 기반 필터링 및 청킹 작업을 수행하기 위한 필수 전제 조건
